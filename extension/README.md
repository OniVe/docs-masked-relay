# DocsMasked Relay

Браузерное расширение для Chrome, Edge и Safari, которое помогает отправлять файлы в
ChatGPT с меньшим риском для персональных данных. Оно работает локально: находит данные
в файле, заменяет их метками, а при скачивании возвращает исходные значения из
зашифрованного хранилища.

## Простыми словами

DocsMasked Relay — расширение для браузера, которое помогает отправлять файлы в ChatGPT
с меньшим риском для персональных данных. Перед отправкой оно находит в файле имена,
телефоны, адреса, email и другие данные по вашим настройкам и заменяет их метками вида
`[[XXXXX_PERSON_1]]`. В ChatGPT уходит только обезличенная копия файла и такое же
обезличенное имя; исходные значения, ключи и хранилище остаются на вашем компьютере.
Когда вы скачиваете файл с метками, расширение возвращает исходные значения из
локального зашифрованного хранилища. Всё работает в браузере: у расширения нет сервера,
аккаунта, телеметрии и рекламы. Но это не защита от OpenAI: отправленный файл хранится у
них по их правилам, а расширение не гарантирует соблюдение 152-ФЗ и не заменяет
юридическую консультацию. Автоматические проверки могут ошибаться, PDF после необратимого
удаления не восстановить, а сканы без текстового слоя не поддерживаются.

### Что уходит в ChatGPT и что остаётся локально

| Уходит в ChatGPT                                              | Остаётся на вашем устройстве                                     |
| ------------------------------------------------------------- | ---------------------------------------------------------------- |
| Обезличенная копия файла с метками вместо персональных данных | Исходный файл и исходные значения данных                         |
| Обезличенное имя файла, его размер и тип                      | Зашифрованное хранилище соответствий «метка → исходное значение» |
| Обычные запросы, которые делает сам сайт ChatGPT              | Ключи шифрования, настройки и список исключений                  |

Важно: после отправки обезличенная копия хранится у OpenAI по правилам OpenAI. Расширение
не может удалить её оттуда и не защищает от самого сервиса ChatGPT.

### Словарь терминов

| Термин                           | Что это значит                                                                                                                             |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| Персональные данные (PII)        | Имена, телефоны, email, адреса, номера документов и другие сведения, по которым можно узнать человека.                                     |
| Метка (tag)                      | След, который ставится вместо значения, например `[[XXXXX_PERSON_1]]`. По метке расширение находит исходное значение в хранилище.          |
| Обезличенный файл                | Копия файла, в которой персональные данные заменены метками. Именно она уходит в ChatGPT.                                                  |
| Хранилище (vault)                | Зашифрованное локальное хранилище соответствий между метками и исходными значениями. Находится только на вашем устройстве.                 |
| Код хранилища (prefix)           | Пять символов в начале метки (`XXXXX`), которые привязывают метку к конкретному хранилищу.                                                 |
| Парольная фраза                  | Дополнительный пароль для хранилища. Он защищает ключ шифрования; потеря пароля может означать потерю доступа к сохранённым соответствиям. |
| Проверка утечек (LeakGuard)      | Дополнительная проверка, которая ищет оставшиеся персональные данные и блокирует небезопасную отправку.                                    |
| Список исключений (allowlist)    | Слова и термины, которые не нужно заменять метками.                                                                                        |
| Необратимое удаление (redaction) | Удаление данных из PDF без возможности восстановления.                                                                                     |
| Распознавание текста (OCR)       | Технология, которая читает текст с картинок и сканов. В этой версии не поддерживается.                                                     |
| Старые форматы (legacy)          | Файлы `.doc` и `.xls`. Расширение конвертирует их в `.docx` и `.xlsx`.                                                                     |

## Что делает

| Сценарий                   | Поведение                                                                                                                                        |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| Загрузка файла в чат       | Расширение перехватывает файл, локально заменяет персональные данные метками и отправляет в ChatGPT только обезличенные байты и обезличенное имя |
| Скачивание файла с метками | Возвращает исходные байты и имя из хранилища                                                                                                     |
| Скачивание без меток       | Сохраняет файл без изменений                                                                                                                     |
| Хранилище заблокировано    | Загрузка отменяется (безопасный отказ), скачивание сохраняет файл без изменений                                                                  |
| Перехват выключен          | Файлы проходят без обработки, перезагружать вкладку не нужно                                                                                     |
| Ручной режим               | В окне расширения можно нажать «Анонимизировать» или «Восстановить» для выбранного файла                                                         |

Форматы: DOCX, XLSX, TXT, MD, JSON и построчный JSON (JSONL), XML, PDF, а также старые
форматы DOC/XLS.

## Установка в Chrome / Edge (unpacked)

1. `bun run build`.
2. Откройте `chrome://extensions` (или `edge://extensions`), включите Developer mode.
3. «Load unpacked» → выберите `extension/.output/chrome-mv3`.
4. Откройте <https://chatgpt.com/> и проверьте в DevTools:
   - `document.documentElement.dataset.dmRelay` → `"isolated"`;
   - `window.__DM_RELAY_MAIN__` → `true`;
   - `document.documentElement.dataset.dmProtection` → `"on"`/`"off"`.

Иконка расширения открывает окно расширения.

## Использование

### Окно расширения

- **Перехват файлов включён** — выключение останавливает перехват сразу, без перезагрузки
  вкладки. Ручной режим при выключенном перехвате тоже не работает.
- **Хранилище** — статус «Разблокирован/Заблокирован», текущий чат и его код хранилища,
  список хранилищ (код, число чатов, дата обновления).
- **Парольная фраза** — если хранилище заблокировано, окно расширения показывает форму
  разблокировки. Неверная фраза → «Неверная парольная фраза».
- **Ручной режим** — выберите файл и нажмите «Анонимизировать» или «Восстановить».
  Результат скачивается как обычный файл; разрешение `downloads` не запрашивается.
- **Настройки** — кнопка открывает страницу настроек.
- **Последнее действие** — только счётчики и статусы, без имён файлов и персональных
  данных.

### Настройки

Открываются в отдельной вкладке (`options_ui.open_in_tab: true`); при ширине окна ≥1024 px
настройки располагаются в две колонки, в узком окне — в одну.

- Включение перехвата, лимит файла (1–100 МБ), замена имён файлов, автоблокировка 1–240 мин.
- Категории персональных данных (флажки), даты и ссылки, агрессивный режим, проверка
  утечек, `skipCode`.
- Свои термины и список исключений — по одному значению на строку. Для терминов можно
  задать метку замены (`CLIENT`) глобально или в строке: `Иванов Иван => CLIENT`; метка
  входит в состав итоговой метки, произвольная текстовая замена не поддерживается (иначе
  восстановление невозможно).
- Очистка метаданных показана включённой и недоступна для выключения: обработчики форматов
  всегда удаляют метаданные.
- Парольная фраза: включить / сменить (нужна текущая) / снять (нужна текущая).
  Предупреждение: потеря пароля означает потерю доступа к соответствиям в хранилище.
- Хранилище: список, удаление, экспорт зашифрованного JSON, импорт JSON, статус.
- Очистка данных: удаляет хранилище, ключи и настройки без возможности отмены.
- Знакомство при первом запуске: что остаётся локально, зачем нужны разрешения, какие есть
  ограничения.

### Как это работает

1. Скрипт страницы замечает запрос на загрузку файла в ChatGPT и передаёт файл расширению.
2. Расширение находит персональные данные, заменяет их метками и сохраняет соответствия в
   зашифрованное хранилище.
3. В ChatGPT уходят только обезличенные байты; имя файла и его размер согласованы с
   обезличенной копией. Уведомление на странице показывает счётчики и до трёх
   предупреждений (остальные — в окне расширения).
4. При скачивании файла расширение находит метки по коду хранилища и возвращает исходные
   имена и байты.

Технические подробности реализации — в [`SECURITY.md`](./SECURITY.md) и в спецификации
[`../docs/planning/extension-spec.md`](../docs/planning/extension-spec.md).

## Ограничения

- Не защищает от OpenAI: отправленный обезличенный файл хранится у них по их политике.
- Не юридическая консультация и не гарантия соблюдения 152-ФЗ.
- **PDF в одну сторону**: необратимое удаление нельзя отменить, восстановить PDF из
  обезличенной копии нельзя.
- Сканы PDF без текстового слоя блокируются: распознавания текста в этой версии нет.
- Изображения, встроенные объекты, диаграммы и вложения внутри документов не проверяются.
- Старые форматы `.doc` и `.xls` конвертируются в `.docx` и `.xlsx`; вёрстка, стили и
  макросы теряются.
- Автоматическое распознавание вероятностное: может пропустить данные или заменить лишнее.
  Проверка утечек снижает риск, но не устраняет его.
- Некоторые структуры отклоняются целиком, если их нельзя обезличить безопасно: числовые
  значения с признаками персональных данных в JSON, XML с DOCTYPE/DTD или неизвестными
  сущностями, повреждённые архивы. Это безопасный отказ, а не утечка.
- Протокол chatgpt.com может измениться; запасной вариант — ручной режим.
- Safari: автоматический перехват работает в desktop Safari 18+; iOS не поддерживается.
- Лимит по умолчанию — 25 МБ (до 100 МБ), PDF — до 200 страниц. Большие файлы
  отклоняются.

### Технические подробности ограничений

Эти подробности нужны разработчикам и проверяющим; для обычного использования достаточно
списка выше.

- **PDF.** Очистка удаляет метаданные уровня страницы, `PieceInfo`, `AF`, все аннотации и
  формы (widgets/FreeText), а также рекурсивно вложенные `/Metadata`, `/PieceInfo`, `/AF`,
  `/AA` на image/Form XObjects, шрифтах и паттернах. Сырые байты проверяются на остатки
  персональных данных (до 1000 поверхностей + предупреждение), структура — по всем
  достижимым объектам. Сканы без текстового слоя блокируются; OCR — в следующих версиях.
- **Повторная загрузка.** Повторный PUT/POST на точный `upload_url` из метаданных
  блокируется безопасным отказом до выгрузки страницы (не более 64 URL); оригинал не
  уходит. При переполнении этого предела несовпавшие PUT/POST на известные upload-hosts
  прерываются. Нечитаемый ответ с метаданными (не JSON, больше 64 КБ или без `upload_url`)
  также считается безопасным отказом до выгрузки страницы.
- **JSON/JSONL.** Принимается только строгий JSON (комментарии и висячие запятые
  отклоняются). Строковые значения **и ключи** заменяются метками, `true/false/null` не
  трогаются. Числовые значения с признаками персональных данных (ИНН/СНИЛС/ОГРН/карта/
  счёт/телефон по Луну) отклоняют файл: число нельзя заменить, не сменив тип. Строка из
  длинной цифровой серии (≥7 цифр, например `123456789`) отклоняется проверкой утечек с
  понятной ошибкой — это принятая политика безопасного отказа, а не утечка. Контекст имени
  (`first/last/middle/surname/.../фио/имя/фамилия/отчество`) обрабатывается с учётом роли
  поля: PERSON или однословное имя/фамилия/отчество; покрыты несмежные поля, разные уровни
  и массивы, каждое значение получает отдельную метку. Соседние `first`/`last`-поля
  по-прежнему склеиваются для проверки полного ФИО. JSONL обрабатывается построчно; ошибка
  любой строки отклоняет весь файл.
- **XML.** DOCTYPE/DTD и неизвестные entities отклоняются; текстовые узлы, CDATA и значения
  атрибутов заменяются метками. `xml:lang` и `xml:space` проверяются, неверные значения
  приводят к безопасному отказу; объявления namespace структурны. `xml:base`, `xml:id` и
  прочие `xml:*` заменяются метками; URI/identifier делится на сегменты,
  percent-декодируется, и имя в пути (`/ivan_petrov`, `/Иван_Петров`) или одиночный id
  заменяется всем значением с точным восстановлением. Имена элементов/атрибутов и
  namespace URI не заменяются, но персональные данные в них (например, `<Иванов_Иван>`,
  `<ivan/>`, `xmlns:x="urn:Иванов"`) приводят к безопасному отказу; полевой список
  исключений (`Фамилия/Имя/Отчество/first/last/name/...`) проходит. Имена в элементах и
  атрибутах обрабатываются с учётом роли в любом порядке, включая CDATA, вложенные
  дочерние элементы и разных родителей; соседние `first`/`last` склеиваются для проверки
  полного ФИО. Комментарии и processing instructions очищаются необратимо (не
  восстанавливаются). CDATA с персональными данными при замене превращается в обычный
  текст; метка кодировки в declaration восстанавливается дословно. Mixed EOL без
  персональных данных восстанавливается побайтово. URI с userinfo
  (`https://ivan:petrov@example.ru/path`, `//user@host`) в тексте, CDATA и любом
  неструктурном атрибуте заменяется с сохранением текста; имя в пути URI заменяется также
  в тексте/CDATA (`See https://example.ru/ivan now`) и в обычных атрибутах
  (`url=".../ivan"`, `urn="urn:ivan"`), а `mailto:` с email сохраняет метку email.
  Namespace URI проверяется в сыром и одном percent-декодированном виде; пустой
  `xml:lang=""` допустим, PERSON-подтег (`en-Ivan`) отклоняется. Принятое ограничение:
  структурные имена, цель processing instruction и namespace URI — это схема документа,
  а не пользовательские данные; достоверные персональные данные в них приводят к
  безопасному отказу. Одиночные не-словарные латинские фамилии — граница охвата
  детектора (словарь не расширяется), избыточная блокировка `<roman>` — принятый
  безопасный отказ. Общие значения `scheme:value` в обычном атрибуте (`Chapter:Ivan`)
  могут быть избыточно заменены как PERSON (принято: безопасный отказ, восстановление
  точное, утечки нет). Double-encoded или повреждённый percent-namespace (`urn:%25D0...`,
  `%ZZ`) проходит один percent-decode — это синтетический структурный URI, вне охвата;
  достоверные персональные данные на одном уровне кодирования по-прежнему приводят к
  безопасному отказу; непрозрачный `urn:ivan` в тексте/CDATA не анализируется (вне
  охвата), обычные атрибуты покрыты, userinfo/path в прозе заменяются. Двоичный `.txt` с
  printable-префиксом может пройти sniff; MD со смешанными переводами строк не
  перенормализуется. Лимиты: глубина 200, 1M узлов.
- **Типы файлов и маршрутизация.** Расширение важнее MIME (`.xml` + `application/json` —
  XML, `.json` + `text/markdown` — JSON); PDF — только `.pdf` или неизвестное расширение +
  `application/pdf`; обезличенный MIME — `application/json`/`application/x-ndjson`/
  `application/xml` (`text/xml` при `text/xml` на входе). Для скачивания без имени
  `application/json`/NDJSON/XML дают `download.json`/`download.jsonl`/`download.xml`.
  При восстановлении приоритет у текстового content-type, метаданные — запасной вариант;
  двоичный `.txt/.md/.json/.xml` с меткой требует printable/UTF-8 sniff и иначе не
  восстанавливается. TXT сохраняет смешанные переводы строк побайтово.
- **DOCX/XLSX.** Сложные документы (SmartArt, встроенные объекты, редкие структуры) могут
  проверяться не полностью; ошибка разбора приводит к безопасному отказу.
- **Имена заглавными.** Словарные полные ФИО, обратный порядок и инициалы покрыты; вне
  словаря остаются фамилия с отчеством без имени, произвольные перестановки, юридические
  формы и stopword+initials — принятое ограничение. Избыточная замена названий
  городов/стран как PERSON принята (восстановление точное). Прямая вставка сущностей в
  хранилище требует `refreshVaultIndex` (N2, см. `src/core/vault.ts`).

## Chrome Web Store

- Один продукт: локальная защита персональных данных в файлах для ChatGPT; без рекламы и
  аналитики.
- Политика конфиденциальности: [`PRIVACY.md`](./PRIVACY.md); Limited Use: данные не

- Разрешения: `storage`, `unlimitedStorage`, `offscreen`; доступ к сайтам — только
  ChatGPT/OpenAI.
- Удалённого кода нет, WASM-модули входят в пакет, CSP с `wasm-unsafe-eval`.
- `bun run zip` кладёт в архив manifest, popup/options, background, content scripts,
  offscreen.html, wasm/worker и иконки. Размер и состав проверяйте перед загрузкой.
- Обоснование `offscreen`, доступа к сайтам и обработки персональных данных — в разделе
  Privacy practices.

## Safari (macOS only)

`bun run build:safari` на Windows/Linux создаёт только `.output/safari-mv3` и проверяет
manifest/файлы. Собрать Xcode-проект, подписать и протестировать можно только на macOS.

Кратко:

```bash
bun run build:safari
xcrun safari-web-extension-converter .output/safari-mv3 \
  --project-location build/safari \
  --bundle-identifier com.example.docs-masked-relay \
  --app-name "DocsMasked Relay" --swift
open build/safari/DocsMasked\ Relay/DocsMasked\ Relay.xcodeproj
```

Далее в Xcode: signing team, bundle id, version/build, `PrivacyInfo.xcprivacy`, App Store
или Developer ID + notarization. Подробно — [`docs/safari-build.md`](./docs/safari-build.md).

Safari manifest: `background.scripts` + `persistent:false`, без `offscreen`/`downloads`;
PDF обрабатывается в background page. Требуется Safari 18+ (static MAIN world).

## Тесты

- Unit: детекторы, метки/восстановление, хранилище/ключи/пароль, экспорт/импорт, лимиты,
  router, настройки, протокол bridge (включая `LOCKED`/`DISABLED` и settings push),
  JSON/JSONL (ключи/строки/числа/escapes/JSONL/BOM/EOL, role-aware first/last/3-part,
  проверка утечек длинных цифр), XML (namespaces/CDATA/attrs/comments/PI/DTD/UTF-16/1251,
  `xml:*`-значения и URI path/lone id, structural allowlist/Latin, xml:lang/space
  validation, role-aware name-элементы/атрибуты, declaration label, mixed EOL),
  extension-first routing, PDF `.pdf`/unknown-extension routing, response-MIME priority,
  binary `.txt` sniff, download body-probe trust, TXT mixed EOL.
- E2E: mock chatgpt.com + unpacked extension; upload/download/PDF; options persistence;
  popup toggle; lock/unlock; export/import UI; clear data. JSON/XML e2e в M8 не
  запускался (ограничение окружения Windows) — покрытие этих форматов unit/static.
- E2E никогда не обращается к живому ChatGPT.
- Harness fail-not-skip (H3): отсутствие сборки/манифеста или падение запуска Chromium
  валит suite, а не пропускает тесты; зелёного skip при сломанном окружении быть не может.
- Один worker (H4): `bun run test:e2e` передаёт `playwright test --workers=1`; не
  добавляйте `--workers=N` — N процессов против одного профиля недопустимы.
- Сброс между тестами (H5): страницы, cookies, `storage.local/session`, `dm:clear-data`,
  настройки по умолчанию и HTTP-кэш (CDP `Network.clearBrowserCache`). Состояние service
  worker намеренно не останавливается (это конфликтовало бы с `dm:clear-data`), поэтому
  тесты не должны полагаться на его состояние в памяти.
- `DM_CHROMIUM_EXECUTABLE=/path/to/chrome` — принудительный бинарник для Playwright.
