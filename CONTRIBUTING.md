# Contributing to DocsMasked Relay

Спасибо за интерес к проекту. Это локальное браузерное расширение, работающее с
потенциально чувствительными файлами, поэтому к изменениям предъявляются повышенные
требования к безопасности и тестам.

## Требования

- Bun 1.4.2 (версия закреплена в CI) и Node.js 24.
- Chrome или Edge stable для ручной проверки.
- Rust + target `wasm32-unknown-unknown` — только если меняете код в `extension/wasm/`.
- macOS + Xcode — только для Safari-сборки и подписи.

## Настройка

```bash
cd extension
bun install --frozen-lockfile
bun run test
bun run build
```

`bun install` выполняет `wxt prepare`; сборка не требует Rust, потому что WASM-артефакты
закоммичены.

## Проверки перед PR

```bash
cd extension
bun run ci        # Biome + tsc --noEmit + Vitest
bun run build     # Chrome MV3 → .output/chrome-mv3
bun run zip       # .output/docs-masked-relay-<version>-chrome.zip
```

Ожидаемый unit-прогон — 684 теста в 46 файлах; Biome проверяет 158 файлов. Если меняете
поведение, добавляйте тесты. Для fail-closed сценариев тест должен подтверждать отказ, а
не только успешный путь.

### E2E

E2E не входит в CI и запускается только явно:

```bash
cd extension
bun run test:e2e
```

Harness использует один worker, постоянный профиль и блокировку запуска. **Не добавляйте
`--workers=N`** и не запускайте несколько прогонов параллельно. На Windows пустой
persistent-профиль Chromium ранее приводил к событиям 4625 и блокировке учётной записи;
после статического исправления harness полный e2e в этом окружении не перезапускался.
Считайте e2e отдельным, контролируемым прогоном. Подробности —
[`docs/planning/e2e-harness-fix.md`](docs/planning/e2e-harness-fix.md).

## Фикстуры и данные

- **Никаких реальных PII.** Используйте только синтетические имена, телефоны, адреса и
  документы. Допустимые домены — `example.com`, `example.ru`, `example.test`,
  `example.invalid`.
- Не добавляйте реальные договоры, письма, сканы, скриншоты чатов, экспорты vault или
  данные клиентов.
- Бинарные фикстуры `.doc` из корпуса word-extractor допустимы только с сохранённой
  атрибуцией в `extension/tests/fixtures/legacy/ATTRIBUTION.md`.
- Не добавляйте в тесты или документацию локальные абсолютные пути, имена пользователей
  и машин.

## Секреты и ключи

- Никогда не коммитьте `.pem`, `.crx`, пароли, токены, store credentials, cookies и
  приватные ключи. `installer/enterprise` использует `key.pem` для подписи обновлений —
  он должен оставаться вне репозитория.
- Не добавляйте `.env`, вывод сборки, `node_modules`, `.output`, `dist`, `staging`,
  Playwright-отчёты и zip-архивы.
- Не публикуйте уязвимость в открытом issue; см. [`SECURITY.md`](SECURITY.md).

## Стиль кода

- TypeScript, strict-режим; не отключайте проверки типов без причины.
- Форматирование и lint — Biome: 2 пробела, LF, одинарные кавычки, ширина 100,
  trailing commas. Запускайте `bun run check:fix` перед коммитом.
- Следуйте структуре каталогов и именованию соседнего кода. Держите изменения
  сфокусированными; не смешивайте рефакторинг и поведенческие правки.
- Ошибки и логи не должны содержать значения PII, имена файлов, пароли и ключи.
  Пользовательские тексты ошибок — константы.
- Для изменений в детекторах, форматах, vault, bridge или interception объясните
  модель угроз и поведение при отказе.

## Pull requests

1. Сделайте fork и отдельную ветку.
2. Опишите проблему, решение и риск для приватности/безопасности.
3. Приложите результаты `bun run ci`, `bun run build` (и e2e, если применимо).
4. Убедитесь, что в diff нет секретов, реальных PII и артефактов сборки.
5. Дождитесь review; изменения в security-критичных путях требуют отдельной проверки.

Не выполняйте force-push в чужую ветку и не меняйте версию/Chrome-листинги без
необходимости.

## Лицензия и DCO

Проект распространяется по MIT (см. [`LICENSE`](LICENSE)). Отправляя PR, вы соглашаетесь,
что ваш вклад лицензируется на тех же условиях. Используйте DCO-style sign-off:

```bash
git commit -s -m "Your change"
```

В сообщении коммита появится `Signed-off-by: Name <email>`, подтверждающий право
передавать вклад в проект. Не указывайте чужой email и не подписывайте коммиты от имени
других людей.
