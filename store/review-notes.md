# Заметки для проверяющего — DocsMasked Relay 0.2.0

Эти заметки описывают, что именно может проверить проверяющий. Они намеренно не обещают
того, чего расширение не делает.

- Пакет: `.output/docs-masked-relay-0.2.0-chrome.zip` (MV3; `manifest.json` в корне zip).
- Язык интерфейса: русский. В интерфейсе используется слово «хранилище»; английское `vault`
  в документации и коде — то же самое.
- Аккаунт, сервер, телеметрия и удалённый код не нужны и не используются.
- Используйте только **синтетические** имена, телефоны и email. Не загружайте реальные
  персональные данные.

## 0. Что такое хранилище

**Хранилище (vault)** — зашифрованное локальное хранилище соответствий. Когда расширение
заменяет имя, телефон или email меткой вида `[[XXXXX_PERSON_1]]`, оно записывает пару
«метка → исходное значение» в хранилище на этом устройстве. При скачивании файла расширение
находит нужную пару по коду хранилища (5 символов) и возвращает исходное значение. Хранилище
не покидает устройство; в ChatGPT уходит только обезличенная копия файла.

## 1. Установка расширения

1. Распакуйте пакет в локальную папку.
2. Откройте `chrome://extensions` (или `edge://extensions`), включите **Режим разработчика**
   (Developer mode).
3. **Загрузить распакованное расширение** (Load unpacked) → выберите распакованную папку (в
   ней должен лежать `manifest.json`).
4. Закрепите расширение и откройте его окно. Нажмите **Настройки**: страница настроек
   открывается в **отдельной вкладке браузера** (`options_ui.open_in_tab: true`), а не в
   узком встроенном окне. При ширине окна 1024 px и больше настройки располагаются в две
   колонки; в более узком окне — в одну. Знакомство при первом запуске объясняет, что
   остаётся локально, а что уходит в ChatGPT.

Ожидаемо: в консоли нет ошибок расширения; в окне видны статус защиты, статус хранилища и
ручной режим.

## 2. Ручное обезличивание (работает без ChatGPT)

1. Откройте окно расширения → **Ручной режим** → **Анонимизировать файл**.
2. Выберите синтетический файл `.txt`, например:

   ```text
   Иванов Иван Иванович
   Phone: +7 999 123-45-67
   Email: ivan.ivanov@example.com
   ```

3. Нажмите **Анонимизировать и скачать**.
4. Откройте скачанный файл.

Ожидаемо: скачивается новый файл; персональные данные заменены метками вида
`[[XXXXX_PERSON_1]]`, `[[XXXXX_PHONE_1]]`, `[[XXXXX_EMAIL_1]]` (5-символьный код хранилища
у каждого хранилища свой). Исходных значений нет. Этот ручной шаг не делает сетевых
запросов.

## 3. Ручное восстановление (полный цикл)

1. В **Ручном режиме** → **Восстановить файл** выберите обезличенный файл, скачанный выше.
2. Нажмите **Восстановить и скачать**.
3. Сравните с исходным файлом.

Ожидаемо: восстановленный файл содержит исходные значения и совпадает с исходным текстом.
В ручном режиме, если нет ни меток с известным кодом хранилища, ни однозначного совпадения
по хешу обезличенных байтов, восстановление завершается ошибкой `NO_VAULT`, и файл остаётся
как есть: расширение не угадывает данные. Файл без меток, но с совпадением по хешу
возвращается без изменений. Автоматический путь скачивания — отдельное поведение: файл с
известными метками восстанавливается, а неизвестные метки/префикс остаются в нём как есть
(pass-through); это не ручное восстановление.

**Чистое имя файла и совпадение по байтам.** Ручное восстановление принимает и такой
обезличенный файл, в имени которого нет кода хранилища (например, файл переименовали).
Расширение находит запись хранилища по хешу SHA-256 обезличенных байтов, сохранённых этим
устройством, а не только по имени файла. Хеш сохранён для TXT/MD/JSON/XML и для DOCX/XLSX
(включая `.doc`/`.xls`: они сохраняются как созданные DOCX/XLSX). Для старых записей без
сохранённого хеша двоичный файл по-прежнему сопоставляется только по имени — переименованный
двоичный файл из такой записи без хеша не восстановить. Если одинаковые обезличенные байты
совпадают с несколькими записями или несколькими хранилищами, восстановление прекращается с
ошибкой `NO_VAULT`, и файл остаётся обезличенным: расширение никогда не угадывает, какое
соответствие подставлять. Изменённые байты или другой файл не совпадут, а чужой или
изменённый DOCX/XLSX с известной меткой не будет восстановлен: restore проверяет хеш
обезличенных байтов и при несовпадении оставляет файл без изменений.

## 4. Свои правила

**Настройки → Свои правила** позволяют добавить точные термины, которые заменяются метками
в дополнение к встроенным детекторам.

1. **Метка замены** задаёт метку по умолчанию, например `CLIENT`. Допустимы только заглавные
   латинские буквы и цифры; первый символ — буква; до 32 символов. Встроенные метки
   (`PERSON`, `PHONE`, `EMAIL`, …) зарезервированы, при попытке их использовать ставится
   `CUSTOM`.
2. **Дополнительные термины** — по одному точному термину на строку. Строка может задать
   свою метку через `=>` (или `->`):

   ```text
   Иванов Иван => CLIENT
   Проект «Альфа» -> PROJECT
   секрет
   ```

3. Строка без `=>`/`->` использует общую **Метку замены**; с меткой по умолчанию получается
   метка `CUSTOM`.
4. Сохраните настройки и обезличьте синтетический `.txt` с этими терминами в ручном режиме.
   Ожидаемо: вместо терминов будут `[[XXXXX_CLIENT_1]]`, `[[XXXXX_PROJECT_1]]` и
   `[[XXXXX_CUSTOM_1]]`; восстановление вернёт точные исходные строки.

Свои правила задают **только метку, а не произвольный текст замены**. Метка — это средняя
часть `[[<КОД>_<МЕТКА>_<N>]]`; при восстановлении вся метка целиком заменяется исходным
значением из хранилища. Строка вроде `Иванов Иван => [клиент]` не является допустимой
меткой и приводит к `CUSTOM`, а не к вставке произвольного текста — иначе файл нельзя было
бы надёжно восстановить. Если термин входит в более длинное найденное имя человека (например,
`Иванов Иван` в `Иванов Иван Иванович`), маскируется всё имя целиком с меткой термина:
открытый остаток (отчество) не остаётся в файле.

**Полное ФИО и `labels={CUSTOM}` (R21).** Расширение custom-совпадения до максимального
PERSON-спана выполняется до фильтра по включённым категориям. Поэтому даже когда включена
только категория «Свои термины» (`labels={CUSTOM}`), PERSON не создаёт отдельный тег, но
задаёт границу полного имени: `Иванов Иван => CLIENT` при тексте `Иванов Иван Иванович`
даёт один `[[XXXXX_CLIENT_1]]` на всё ФИО, включая отчество.

**Приоритет allowlist.** Термин из allowlist — явный отказ от маскировки. Сравнение точное,
без учёта регистра (не подстрока). Allowlist важнее custom-правила: такой термин не
маскируется и не расширяется, а расширенный полный span повторно проверяется по allowlist.
Если PERSON включён, точно совпавший с allowlist PERSON-спан также подавляется.

**Ограничение стрелки.** Разделитель — первая `=>` или `->` в строке. Термин, содержащий
стрелку, задать нельзя: строка разрежется по первой стрелке.

## 5. Повторная проверка по форматам

Используйте небольшие синтетические файлы. Ожидаемое поведение:

| Формат | Что проверить |
| --- | --- |
| `.txt` / `.md` | Значения заменены метками; текст восстанавливается побайтово (TXT сохраняет смешанные переводы строк). |
| `.json` | Строковые значения и ключи заменяются метками; принимается только строгий JSON (комментарии и висячие запятые отклоняются). Числовые значения, похожие на ИНН/СНИЛС/ОГРН/карту/счёт/телефон, отклоняются целиком, а не заменяются. |
| `.xml` | Текст, CDATA и значения атрибутов заменяются метками; DOCTYPE/DTD и неизвестные сущности отклоняются; комментарии и processing instructions удаляются необратимо. Имена элементов и атрибутов не заменяются. |
| `.docx` | Основной текст, колонтитулы, сноски, комментарии и метаданные заменяются; восстановление возвращает исходный текст. |
| `.xlsx` | Общие и встроенные строки, комментарии и скрытые листы заменяются; числовые ячейки с признаками персональных данных отклоняются; восстановление возвращает исходный текст. |
| `.pdf` | Настоящее необратимое удаление (redaction): текст удаляется из содержимого PDF, а не перекрывается. **В одну сторону**: обезличенный PDF восстановить нельзя. Сканы без текстового слоя блокируются (распознавания текста нет). |
| `.doc` / `.xls` (старые форматы, legacy) | Конвертируются в `.docx`/`.xlsx`; вёрстка и стили могут потеряться; показывается предупреждение. Восстановление возвращает файл с именем `.docx`/`.xlsx`: исходный бинарный формат не восстанавливается. |
| Изображения / встроенные объекты / вложения | Не проверяются; интерфейс сообщает об этом ограничении. |

Большие файлы: лимит по умолчанию — 25 МБ (настраивается до 100 МБ); файлы больше лимита
отклоняются с сообщением, а не обрабатываются частично. Лимит PDF — 200 страниц.

## 6. Блокировка и безопасный отказ

1. В окне расширения нажмите **Заблокировать хранилище**.
2. Попробуйте ручное обезличивание или восстановление: ручной режим отключается с
   сообщением, что хранилище заблокировано; файл не скачивается.
3. На <https://chatgpt.com/> с включённым перехватом попробуйте загрузить поддерживаемый
   файл при заблокированном хранилище.

Ожидаемо: загрузка отменяется (безопасный отказ, fail-closed), чтобы исходные байты не
ушли без замены. Скачивание файлов с метками при блокировке не восстанавливается; файл
сохраняется без изменений (остаётся обезличенным). Разблокируйте ключом устройства или
парольной фразой и повторите.

Варианты разблокировки: ключ устройства (по умолчанию, хранится как неэкспортируемый
`CryptoKey`) или дополнительная парольная фраза (PBKDF2-SHA256, 600 000 итераций).
Неверная парольная фраза приводит к безопасному отказу и не очищает данные. Автоблокировка
по умолчанию — 15 минут бездействия; она очищает ключ из памяти.

## 7. Необязательный автоматический путь (нужен аккаунт ChatGPT)

Что нужно:

- Открытая сессия <https://chatgpt.com/> с входом (своя или предоставленная тестовая; учётные
  данные в расширение не входят).
- Включённый переключатель **Перехватывать файлы в ChatGPT** в окне расширения.
- Поддерживаемый файл в пределах лимита.
- Веб-клиент ChatGPT всё ещё использует тот способ загрузки и скачивания, который
  перехватывает расширение. Если сайт изменится, автоматический перехват может не
  сработать; ручной режим остаётся доступен.

Шаги: загрузите синтетический поддерживаемый файл в чат, затем скачайте его из сообщения.
Ожидаемо: загруженный файл обезличен (метки видны в файле), имя файла обезличено,
скачанная копия восстановлена. Уведомление на странице показывает счётчики и
предупреждения.

Без аккаунта ChatGPT разделы 2–6 — полный локальный путь проверки; автоматический путь
проверить нельзя.

## 8. WebAssembly, удалённый код и CSP

- `pii-scan.wasm` и `codec.wasm` — локальные файлы пакета, собранные из Rust-крейтов в
  `extension/wasm/` исходного репозитория. Команда сборки: `bun run build:wasm`.
- Нет CDN, удалённой конфигурации, удалённых скриптов, `eval`, `new Function` и
  динамического импорта удалённого кода. `WebAssembly` используется только для запуска
  модулей из пакета.
- CSP в manifest: `script-src 'self' 'wasm-unsafe-eval'; object-src 'self'; worker-src 'self'`.
  `wasm-unsafe-eval` нужен для локальной компиляции WebAssembly; он не разрешает удалённые
  скрипты.
- Исходный репозиторий и инструкции по сборке можно предоставить, если проверяющему нужно
  воспроизвести пакет. Минификация стандартная, обфускации нет.

## 9. Известные ограничения (также раскрыты в листинге и политике)

- Удаление данных в PDF необратимо; восстановить PDF нельзя.
- Распознавания текста (OCR) нет: сканы и PDF только из изображений блокируются.
- Изображения, встроенные объекты, диаграммы, OLE/ActiveX и вложения внутри документов не
  проверяются.
- Конвертация старых форматов DOC/XLS теряет вёрстку, стили и макросы.
- Детекторы вероятностные: возможны пропуски и лишние замены; проверка утечек (LeakGuard)
  снижает риск, но не устраняет его.
- Некоторые структурно небезопасные входные данные (числовые значения JSON с признаками
  персональных данных, XML DTD/неизвестные сущности, неразбираемые архивы) отклоняются
  целиком вместо замены.
- Расширение не защищает от хранения и обработки обезличенного файла самим OpenAI, а также
  от скомпрометированной ОС, браузера, профиля или страницы.
- Расширение не является юридической консультацией и не гарантирует соответствие GDPR,
  152-ФЗ или иным требованиям.
- Safari — отдельный канал распространения; этот пакет предназначен для Chrome/Edge MV3.

## 10. Чего проверяющему не стоит ожидать

- Создания аккаунта, входа, оплаты или подписки внутри расширения.
- Облачной синхронизации, сервиса резервных копий, панели аналитики или удалённой
  конфигурации.
- Гарантии, что будут найдены все возможные персональные данные.
- Восстановления PDF или комментариев/processing instructions, удалённых в XML необратимо.
- Доступа к истории чатов ChatGPT, cookies или учётным данным.
